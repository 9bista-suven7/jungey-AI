HOW JUNGEY TV CONNECTS TO AND CONTROLS THE TV
=============================================

Jungey TV talks to a Samsung smart TV (2016 or newer, Tizen) over the home Wi-Fi. There
is no cloud, no Samsung account and no extra hardware: the laptop and the TV speak to
each other directly on the local network, the same way Samsung's own SmartThings phone
app does.

Tested with: Samsung 7 Series 55" (UN55RU7100FXZA, 2019, Tizen).


THE BIG PICTURE
---------------

    You  --(voice)-->  Jungey  --(runs a command)-->  jungey-tv  --(Wi-Fi)-->  Samsung TV
    You  --(clicks)-->  Jungey TV window  ---------------------------(Wi-Fi)-->  Samsung TV

The TV offers four different doors, and Jungey TV uses each for one job:

    Port   Protocol                  Used for                          Needs permission?
    ----   ------------------------  --------------------------------  -----------------
    1900   UPnP / SSDP (UDP)         finding the TV on the network      no
    8001   HTTP (plain)              asking the TV about itself         no
    8002   Secure WebSocket (wss)    pressing buttons, apps list,       yes - "Allow"
                                     opening apps and titles, typing
    8080   DIAL (HTTP)               playing a YouTube video            no
    9, 7   Wake-on-LAN (UDP)         waking the TV from standby         no

Two things on the internet are asked too, for searching - never the TV:

    www.youtube.com/youtubei/v1/search   YouTube's own search, as its website uses it
    apis.justwatch.com/graphql           which films and series stream where


STEP 1 - FINDING THE TV   (Discovery.java)
----------------------------------------

The laptop shouts one message to every device on the network at once (a UPnP
"M-SEARCH" to the multicast address 239.255.255.250, port 1900):

    M-SEARCH * HTTP/1.1
    HOST: 239.255.255.250:1900
    MAN: "ssdp:discover"
    MX: 2
    ST: ssdp:all

Every device that understands UPnP answers - routers, printers, TVs. Jungey TV keeps
the ones whose answer mentions "Samsung", then asks each of them what it is (step 2).
The first Samsung TV found is remembered, so this only happens once.

If discovery cannot work on a network, the address can be given by hand:
    jungey-tv use 192.168.1.20


STEP 2 - ASKING THE TV ABOUT ITSELF   (TvInfo.java)
-------------------------------------------------

A plain web request, no permission needed:

    GET http://<tv-address>:8001/api/v2/

The TV answers with JSON describing itself, for example:

    {
      "device": {
        "name": "[TV] Samsung 7 Series (55)",
        "modelName": "UN55RU7100FXZA",
        "type": "Samsung SmartTV",
        "wifiMac": "xx:xx:xx:xx:xx:xx",
        "PowerState": "on",
        "TokenAuthSupport": "true"
      }
    }

From this Jungey TV learns:
  - the TV's name and model (shown in the window, spoken by Jungey)
  - its network card's MAC address (needed to wake it later - step 7)
  - whether it is "on" or in "standby" (the window checks this every 4 seconds)
  - that it needs a token (TokenAuthSupport), so pairing is required

Detail that mattered: this request must use HTTP/1.1. Java offers to upgrade to HTTP/2
by default, and the TV's small web server hangs up on that offer.


STEP 3 - PAIRING, ONCE   (Remote.java, PinnedTrust.java)
--------------------------------------------------------

Everything that changes something on the TV goes through its remote-control channel, a
secure WebSocket on port 8002:

    wss://<tv-address>:8002/api/v2/channels/samsung.remote.control?name=SnVuZ2V5IFRW

"SnVuZ2V5IFRW" is "Jungey TV" in Base64 - it is the name the TV shows on screen and lists
under Settings > General > External Device Manager > Device Connection Manager.

The first time, the TV shows a pop-up: "Allow Jungey TV to connect?"
  - Allow  -> the TV sends back   {"event":"ms.channel.connect","data":{"token":"12345678",...}}
  - Deny   -> the TV sends back   {"event":"ms.channel.unauthorized"}
  - nobody answers in 30 seconds  {"event":"ms.channel.timeOut"}

On Allow, Jungey TV saves the token. Every later connection adds it to the address
(...&token=12345678) and the TV lets it straight in, with no pop-up.

The TV's certificate:
  The connection is encrypted (TLS), but the TV signs it with its own certificate,
  issued to "SmartViewSDK" rather than to an address, so normal certificate checks can
  never pass. Instead, Jungey TV records the certificate's SHA-256 fingerprint the moment
  pairing succeeds ("pinning"). From then on, only that exact certificate is accepted.
  If anything else ever answers at the TV's address, Jungey TV refuses to talk to it.
  (After replacing or resetting the TV:  jungey-tv pair --reset)


STEP 4 - PRESSING BUTTONS   (Remote.key, Keys.java)
---------------------------------------------------

Over the open WebSocket, each button press is one small JSON message:

    {
      "method": "ms.remote.control",
      "params": {
        "Cmd": "Click",
        "DataOfCmd": "KEY_VOLUP",
        "Option": "false",
        "TypeOfRemote": "SendRemoteKey"
      }
    }

Keys.java turns the words people use into the TV's key names:

    volume up -> KEY_VOLUP        mute      -> KEY_MUTE       home    -> KEY_HOME
    volume down -> KEY_VOLDOWN    channel up -> KEY_CHUP      back    -> KEY_RETURN
    up/down/left/right -> KEY_UP / KEY_DOWN / KEY_LEFT / KEY_RIGHT
    ok -> KEY_ENTER               hdmi 2    -> KEY_HDMI2      source  -> KEY_SOURCE
    play -> KEY_PLAY              pause     -> KEY_PAUSE      power   -> KEY_POWER

Repeated presses ("volume up 5") are spaced 140 ms apart, because the TV can merge two
presses that arrive too close together. The window keeps the connection open, so each
click answers almost instantly; a single command opens it, presses, and closes it.


STEP 5 - LISTING AND OPENING APPS   (Remote.apps, Remote.launch)
----------------------------------------------------------------

Asking for the installed apps, over the same WebSocket:

    {"method":"ms.channel.emit","params":{"event":"ed.installedApp.get","to":"host"}}

The TV replies with every app, e.g.:

    {"event":"ed.installedApp.get","data":{"data":[
        {"appId":"3201907018807","name":"Netflix","app_type":2},
        {"appId":"111299001912","name":"YouTube","app_type":2}, ... ]}}

Opening one:

    {"method":"ms.channel.emit","params":{"event":"ed.apps.launch","to":"host",
        "data":{"appId":"3201907018807","action_type":"DEEP_LINK"}}}

("DEEP_LINK" for normal apps; "NATIVE_LAUNCH" for the TV's own built-in ones, app_type 4.)

App names are matched loosely, so "prime" finds "Prime Video", "disney plus" finds
"Disney+", and "netflix" finds "Netflix". If the TV is in standby it is turned on first.


STEP 6 - SEARCHING AND PLAYING YOUTUBE   (YouTube.java)
------------------------------------------------------

Two parts:

1. Searching. Jungey TV asks the same service YouTube's website asks when you search:

       POST https://www.youtube.com/youtubei/v1/search
       {"context": {"client": {"clientName": "WEB", "clientVersion": "2.2025...", "gl": "US"}},
        "query": "action movies",
        "params": "EgIQBA=="}                        <- the Movies filter

   The answer is JSON: about twenty results, each with its video ID, title, channel,
   length, views, age and badges ("LIVE", "Free with ads"), and a "continuation" token.
   Sending the token back ({"continuation": "..."}) gives the next twenty - that is the
   "More results" button. No Google account or API key.

   The filters are the website's own "sp" values:

       Videos   EgIQAQ==      Movies   EgIQBA==      Live     EgJAAQ==
       20+ min  EgIYAg==      Newest   CAI=

   Thumbnails come from https://i.ytimg.com/vi/<id>/mqdefault.jpg (320 x 180).
   "play X" with no choosing plays the first result; a pasted link skips the search.

2. Playing it. This uses DIAL, the protocol a phone uses when you press "cast":

       POST http://<tv-address>:8080/ws/apps/YouTube
       Content-Type: text/plain
       body:  v=jfKfPfyJRdk

   The TV's YouTube app opens (if it is not already) and plays that video. DIAL needs no
   token. The window then shows the video's thumbnail from
   https://i.ytimg.com/vi/<id>/hqdefault.jpg under "Now playing".


STEP 7 - FINDING MOVIES AND SHOWS IN YOUR APPS   (Catalog.java, Services.java)
------------------------------------------------------------------------------

Netflix, Prime Video and the others have no search anyone else can use, so Jungey TV
asks JustWatch - the listings behind most "where to watch" sites - with the query its
website uses:

    POST https://apis.justwatch.com/graphql
    popularTitles(country: "US", filter: {searchQuery: "the office"}) {
        title, year, poster, offers { service, how (subscription/free/rent/buy), link } }

Each offer is matched to an app on the TV (Services.java): "Amazon Prime Video" and
"Amazon Video" to Prime Video, "Disney Plus" to Disney+, "Netflix Standard with Ads" to
Netflix, channels sold through Prime Video to Prime Video, and so on. Disc shops and
cable boxes are left out. The country comes from this computer's settings (en_US -> US),
or "country" in tv.json.

Opening a title, over the same WebSocket as opening an app (step 5):

  - Netflix takes a title as a deep link:
        {"method":"ms.channel.emit","params":{"event":"ed.apps.launch","to":"host",
            "data":{"appId":"3201907018807","action_type":"DEEP_LINK",
                    "metaTag":"m=http://api-global.netflix.com/catalog/titles/movies/80057281&source_type=4"}}}
    The number is the title's ID from its netflix.com/title/... link. If the Netflix app
    ignores it, Netflix simply opens at its home screen.
  - A YouTube offer (films YouTube rents or shows free) is a video, and plays by DIAL.
  - Every other app opens at its home screen: they do not accept a title from outside.
    Then the title's name can be typed into the app's search (step 8).


STEP 8 - TYPING ON THE TV   (Remote.text)
-----------------------------------------

When an app puts the TV's on-screen keyboard up - Netflix's search, a login box - the TV
says so on the WebSocket:

    {"event":"ms.remote.imeStart", ...}

The window hears this and puts the cursor in its "Type on the TV" box. Whatever is typed
there is sent as text, and then "done":

    {"method":"ms.remote.control","params":{"Cmd":"<the text, Base64>",
        "DataOfCmd":"base64","TypeOfRemote":"SendInputString"}}
    {"method":"ms.remote.control","params":{"TypeOfRemote":"SendInputEnd"}}

With no keyboard open on the TV, the text goes nowhere.


STEP 9 - POWER   (SamsungTv.turnOn / turnOff, WakeOnLan.java)
------------------------------------------------------------

Turning OFF:  if the TV says it is "on", send KEY_POWER over the WebSocket.

Turning ON depends on how asleep the TV is:
  - "standby" (it still answers on port 8001): send KEY_POWER over the WebSocket.
  - not answering at all: send a Wake-on-LAN "magic packet" - 6 bytes of FF followed by
    the TV's MAC address repeated 16 times (102 bytes) - to the whole network on UDP
    ports 9 and 7, three times. Then check every second, for up to 20 seconds, until
    the TV reports "on".

  Waking from deep standby only works with this enabled on the TV:
    Settings > General > Network > Expert Settings > Power On with Mobile


HOW JUNGEY USES IT   (Jungey: TvSkill.java)
-------------------------------------------

Jungey does not talk to the TV itself. When a sentence mentions the TV, Jungey's TV skill
turns it into a jungey-tv command, runs it, and says the answer:

    "open Netflix on the TV"             ->  jungey-tv --json open netflix
    "watch Stranger Things on Netflix"   ->  jungey-tv --json watch stranger things on netflix
    "search YouTube for lofi on the TV"  ->  jungey-tv --json search youtube lofi
    "play number two"   (after that)     ->  jungey-tv --json youtube https://youtu.be/<its id>
    "show them"         (after that)     ->  jungey-tv browse youtube lofi   (the window)
    "type friends on the TV"             ->  jungey-tv --json type friends
    "play lofi on YouTube on the TV"     ->  jungey-tv --json youtube lofi
    "TV volume down by 5"                ->  jungey-tv --json volume down 5
    "switch the TV to HDMI 2"            ->  jungey-tv --json source hdmi2
    "turn on the TV"                     ->  jungey-tv --json on
    "pair the TV"                        ->  jungey-tv --json pair

jungey-tv answers with one line of JSON, the message already worded to be spoken:

    {"ok":true,"message":"Opening Netflix on the TV."}
    {"ok":false,"message":"The TV is off or not answering.","problem":"unreachable"}

Sentences without "TV" in them ("volume up", "open Netflix") still control the laptop.


WHERE THINGS ARE KEPT
---------------------

~/.config/jungey-tv/tv.json   - readable by you only (permissions 600)
    host          the TV's address on the network
    country       optional: which country's listings to search (e.g. "US")
    name, model   what the TV calls itself
    mac           its network card's address, for waking it
    token         the TV's permission, given when Allow was pressed
    certSha256    the TV's certificate fingerprint, pinned at pairing

Delete this file to make Jungey TV forget the TV completely. The TV itself keeps
"Jungey TV" in its Device Connection Manager list, where it can also be removed.


THE CODE, FILE BY FILE   (apps/tv/src/main/java/dev/suven/jungeytv/)
--------------------------------------------------------------------

    Launcher.java          no arguments -> the window; arguments -> a command
    Cli.java               the jungey-tv commands and their --json replies
    tv/Discovery.java      step 1: the UPnP search
    tv/TvInfo.java         step 2: the TV's description on port 8001
    tv/Remote.java         steps 3-5: the secure WebSocket - pairing, keys, apps
    tv/PinnedTrust.java    step 3: accepting only the TV's own certificate
    tv/Keys.java           step 4: button names -> KEY_ names
    tv/YouTube.java        step 6: search, filters, more results, and playing over DIAL
    tv/Catalog.java        step 7: films and series, and where they stream
    tv/Services.java       step 7: services -> the TV's apps, and Netflix's deep link
    tv/WakeOnLan.java      step 9: the magic packet
    tv/SamsungTv.java      puts it all together: on, off, press, apps, open, youtube,
                           watch, type
    tv/TvSettings.java     ~/.config/jungey-tv/tv.json
    ui/ControlCenter.java  the window
    ui/SearchSheet.java    the search screen: YouTube and Movies & shows tabs


WHAT IT CANNOT DO (YET)
-----------------------

  - Read or set the exact volume level - the remote channel only has up/down buttons.
  - Know which app or channel is showing right now.
  - Open a title inside Prime Video, Disney+, Hulu and the rest - it opens the app, and the
    title's name can then be typed into its search from the window.
  - Search inside the TV's apps' own catalogues - the listings are JustWatch's, which can
    lag a day or two behind what an app has added.
  - Control Samsung TVs from before 2016, which use a different, older protocol.
